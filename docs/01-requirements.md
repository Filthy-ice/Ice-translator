# 需求文档 — Ice Translator v1.0

优先级：**M**=Must（不做即失败）　**S**=Should（本轮尽量）　**C**=Could（有余力）
每条需求的"验收"列是测试用例文档里对应 TC 的判定依据，必须可观察、可复现。

---

## 1. 用户与使用场景

| 角色 | 场景 | 关键诉求 |
|---|---|---|
| 开发者本人（唯一用户） | 读英文文档/论文时随手翻译一段 | 不用切窗口、不用打开浏览器 |
| 同上 | 长句、需要语气与专业性的内容 | AI 翻译质量，能带上一点上下文 |
| 同上 | 看到一张带外文的产品截图/PPT/报错弹窗 | 直接得到一张中文的图，而不是手抄 |
| 同上 | 反复出现的术语（如某个产品名） | 术语稳定、前后一致 |

**核心用户故事**

- US-1 作为读者，我希望选中文字后不切换应用就能看到译文，从而不打断阅读。（对应 FR-3、FR-5）
- US-2 作为读者，我希望在"够快"和"够好"之间自己选引擎，而不是被工具替我决定。（FR-1）
- US-3 作为拿到外文截图的人，我希望图直接变成中文图，且原图不被上传。（FR-2）
- US-4 作为长期使用者，我希望工具记住我的语言偏好、窗口位置和术语。（FR-4）

## 2. 功能需求

### FR-1 文本翻译

| 编号 | 优先级 | 需求 | 验收 |
|---|---|---|---|
| FR-1.1 | M | 提供多行源文输入区，支持任意长度（≥ 20,000 字符不崩），实时或按快捷键触发翻译 | 粘贴 18,000 字符文章节选，输入不卡死、能出结果 |
| FR-1.2 | M | 源语言可指定，且提供"自动检测"选项并在结果中回显检测到的语言 | 输入中文/英文/日文各一句，检测回显正确 |
| FR-1.3 | M | 双引擎：`机翻`与 `AI`，可随时切换，切换后对当前源文自动重译；可设默认引擎 | 同句在两引擎下输出不同结果，切换耗时 < 1s 反馈 |
| FR-1.4 | M | 目标语言可选，界面固定提供中英日，其余语言可在设置中启用；记住最近 5 种目标语言 | 改目标语言后重启应用仍是上次选择 |
| FR-1.5 | M | 译文区操作：复制译文、复制"原文+译文对照"、一键替换系统剪贴板为译文 | 三个按钮功能互不串台，复制内容可粘贴验证 |
| FR-1.6 | M | 不可译内容保护：URL、邮箱、代码块（``` 包裹）、`XxxYyy` 形式的标识符、带单位数字（如 12 MB、2026-10-19）不得被翻译或篡改 | 构造含 6 类内容的样句，两引擎输出中这些片段逐字节保持一致 |
| FR-1.7 | M | 引擎失败必须有明确可读错误（超时/401/限流/无 Key），源文不得丢失，且不 panic | 断网、填错 Key、正确 Key 三种情况分别得到对应提示，源文仍在 |
| FR-1.8 | S | 相同源文 + 相同引擎 + 相同语言对命中本地缓存，不发网络请求 | 第二次请求耗时降到 < 5ms 且日志显示 cache hit |
| FR-1.9 | S | AI 引擎允许超长输入时自动分段（≤ 3,500 字符/段）并按序拼回，保持段间术语一致 | 12,000 字符输入能完整返回，且顺序与分段数正确 |

### FR-2 图片翻译

| 编号 | 优先级 | 需求 | 验收 |
|---|---|---|---|
| FR-2.1 | M | 四种图片来源：拖拽图片文件、粘贴剪贴板图片、文件选择器、指定路径 | 每种路径各导入一张图，均能进入 OCR |
| FR-2.2 | M | 本地 OCR（macOS Vision）：输出带**坐标框、文本、置信度**的块级结果，不做任何网络上传 | 对样图集运行，日志与网络抓包证明零外发请求；每块有 bbox 与 conf |
| FR-2.3 | M | 识别结果以可编辑列表呈现，用户可修正错字、删除误识别块、合并/拆分块，修正后再翻译 | 手改一处错字，生成图反映修改 |
| FR-2.4 | M | 译文回填：擦除原文并绘制译文，生成**新图副本**，原图文件不被修改 | 生成后校验原图文件哈希不变；输出图可见中文 |
| FR-2.5 | M | 覆盖层模式：在原文位置之上绘制带底色的译文块，不做像素擦除；复杂背景可用此模式兜底；回填效果可一键切换到此模式 | 同一张渐变背景图，覆盖层模式输出无可读性损失 |
| FR-2.6 | M | 导出：保存 PNG/JPEG 到用户选择路径，或复制图片到剪贴板 | 两种方式都能拿到成品并可被预览打开 |
| FR-2.7 | S | 字号自适应：译文超出原框时先自动缩字号（下限为原字号 55%），仍放不下则标记该块为"降级"并用覆盖层绘制 | 中→德长译文样图，无文字被裁切丢失 |
| FR-2.8 | S | 颜色与对齐还原：从原区域采样主前景色/背景色，保持左/中/右对齐 | 白字深底样图，回填后文字颜色仍为白 |
| FR-2.9 | S | 处理进度可见：分"OCR / 翻译 / 合成"三阶段显示状态与耗时，可取消 | 处理中能取消且不残留半成品 |
| FR-2.10 | C | 区域截图：框选屏幕区域后直接进入图片翻译流程 | — 列入延期项 |

### FR-3 双界面模式

| 编号 | 优先级 | 需求 | 验收 |
|---|---|---|---|
| FR-3.1 | M | **全量模式**：标准窗口，含源文/译文双栏、引擎与语言选择、图片翻译页、历史页、设置页 | 见 P4 界面走查表 |
| FR-3.2 | M | **简洁模式**：窄条窗口（默认 460×96 内容区），无系统标题栏装饰，仅含输入行 + 译文行 + 三个动作图标。**无边框不得导致窗口不可移动**：整条窄窗内容区即为拖动把手，按下后走原生窗口拖拽 | 见 P5 走查表；置顶开启时仍可拖动到屏幕任意位置 |
| FR-3.3 | M | 两模式一键切换（应用内快捷键 + 界面按钮），切换保留当前源文、译文与语言对 | 有内容时切换 20 次，内容不丢、不重复请求 |
| FR-3.4 | M | 简洁模式窗口置顶：开启后覆盖在其他应用窗口之上，关闭后恢复常规层级 | 置顶时全屏其他应用，悬浮条仍可见可点击 |
| FR-3.5 | M | 边缘吸附：简洁模式可拖拽，松手时若距某条屏幕边缘 < 40px 则自动贴边停靠（保留 6px 可见热区）；从停靠态可拖离恢复自由浮动 | 四条边各吸附一次，位置记录准确；拖离后位置不再吸附 |
| FR-3.6 | M | 记忆与恢复：记住当前模式、窗口位置尺寸、置顶状态，重启后恢复；启动时若记录位置已超出当前屏幕可用区，回到屏幕中心 | 拔外接屏后重启，窗口不消失、可找回 |
| FR-3.7 | S | 简洁模式半透明：非聚焦时不透明度 85%，聚焦时 100%，可在设置中关闭该行为 | 观察两态差异，关闭后恒为 100% |
| FR-3.8 | S | 简洁模式支持"剪贴板即翻"：开启后复制文本自动出现在输入行并翻译 | 复制一段英文，悬浮条自动出译文 |
| FR-3.9 | M | **形态切换是同一个窗口的形变**：全量↔简洁之间以 180~220ms 的尺寸/位置补间动画过渡（先展宽再显影内容或反向），不得出现"瞬间跳窗""先黑屏再出现"的硬切；动画期间置顶状态与内容不变，输入不被阻塞 | 连续切换 10 次：每次都能看出是同一窗口在伸缩，无跳变；切换后两端尺寸与 `03-ui-design.md` 一致（±2px）；动画期间点击按钮仍有响应 |

### FR-4 配置、历史与术语

| 编号 | 优先级 | 需求 | 验收 |
|---|---|---|---|
| FR-4.1 | M | 设置页可配：AI 服务的 base_url / model / API Key、默认引擎、默认语言对、界面字号、主题（跟随系统/亮/暗） | 每项改后立即生效并持久化 |
| FR-4.2 | M | API Key 存入 macOS 钥匙串（条目名固定），配置文件与日志中只出现占位引用，不出现明文 | 检查配置文件与所有日志行，无 Key 明文 |
| FR-4.3 | M | 配置目录遵循平台规范（macOS 为 `~/Library/Application Support/IceTranslator`），首次运行自动创建，损坏文件不导致启动失败 | 写入畸形 TOML 后启动，能降级为默认配置并提示 |
| FR-4.4 | S | 翻译历史：本地保存最近 500 条（文本 + 引擎 + 语言对 + 时间），可搜索、可重新载入、可清空 | 翻译 3 条后搜索关键词能命中并可一键回显 |
| FR-4.5 | S | 术语表：用户可维护 `原文 → 译文` 列表，AI 引擎注入提示词，机翻引擎做译后替换；即时生效 | 加一条术语后含该词的样句两引擎均使用指定译法 |

### FR-5 系统集成

| 编号 | 优先级 | 需求 | 验收 |
|---|---|---|---|
| FR-5.1 | M | 应用内快捷键：翻译（Enter / Cmd+Enter）、切换模式、复制译文、关闭/最小化简洁条 | 逐个按键验证，无冲突、无失效 |
| FR-5.2 | M | 关闭窗口不退出进程：macOS 上进入 Dock/菜单栏常驻，再次点击图标恢复窗口，Cmd+Q 才真正退出 | 关窗后进程仍在且 CPU < 1%，恢复后状态完好 |
| FR-5.3 | S | 系统休眠/唤醒、显示器插拔后窗口状态不异常（不白屏、不越界） | 插拔外接屏各一次，界面正常 |

## 3. 非功能需求

| 编号 | 优先级 | 需求 | 验收 |
|---|---|---|---|
| NFR-1 | M | 性能：机翻 P50 < 800ms；文本输入到 UI 响应 < 16ms（不掉帧）；1080p 截图本地 OCR < 1.5s | 用 20 次采样脚本测得 P50 达标并留档 |
| NFR-2 | M | 健壮性：任何网络/图像/字体异常不得 panic 主线程；图像流水线失败只影响当次任务 | 全程跑完无 panic；构造畸形图片不崩 |
| NFR-3 | M | 隐私：图片 OCR 与合成全程本地；文本只在用户主动触发时外发；日志不记录源文全文（只记长度与哈希前 8 位） | 审查日志输出实现与样例 |
| NFR-4 | M | 界面语言为简体中文；中英文混排不破版。**配色默认跟随系统深浅色**（含自动切换），同时设置里保留三态开关：跟随系统 / 强制浅色 / 强制深色，选择即时生效并持久化 | 系统切深浅色后应用在下一次重绘跟随（≤1s）；锁定为浅色后系统改深色不变；两主题下所有文本可读、对比度目测达标 |
| NFR-5 | S | 资源占用：空闲（简洁模式停靠）常驻内存 < 200MB，CPU < 1%；release 产物 < 40MB | Activity Monitor / `du` 实测留档 |
| NFR-6 | M | 可维护性：`ice-core`/`ice-providers`/`ice-vision` 不依赖任何 UI crate，可独立单测 | `cargo tree` 验证依赖方向，无 UI 依赖 |
| NFR-7 | S | 跨平台：Windows/Linux 下 `cargo check` 通过且文本翻译功能可用；OCR 在非 macOS 明确提示"当前平台不支持" | CI 或本地三目标交叉检查留档 |
| NFR-8 | C | 可访问性：支持系统字号缩放跟随、键盘可达全部主要操作 | 走查 |

## 4. 接口与数据约束

1. **AI 引擎**：OpenAI 兼容 `POST {base_url}/chat/completions`，`Authorization: Bearer <key>`；模型名可配，默认由用户在设置里填。不新增私有协议。
2. **机翻引擎**：零配置可用（不需用户注册或提供 Key）。具体端点在 P3 实测确定并写入 ADR-004；若唯一可用免费端点不稳定，则降级为"内置离线词表 + 需用户自备 Key"的方案并在验收报告中说明。
3. **配置格式**：TOML。字段设计见 `02-architecture.md` 的 `Config` 结构。
4. **历史格式**：JSON Lines，追加写，可被用户用文本编辑器打开。
5. **术语表**：TOML 内数组，`[[term]] source="..." target="..."`。

## 5. 约束与假设

- 假设 macOS ≥ 12（Vision `VNRecognizeTextRequest` 可用），实际目标 14+。
- 假设用户自备 AI 服务 Key；未配置时应用仍必须完全可用（走机翻）。
- 不做用户账号、不做遥测、不做自动更新。
- 单实例运行：第二个实例启动时给出提示并退出（避免钥匙串与历史文件写冲突）。
