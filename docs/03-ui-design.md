# 界面设计 — 全量模式与简洁模式

本文件的"控件清单"是 P4/P5 人工走查的对照表：走查时逐行勾选，位置或命名与本表不符即为缺陷。

## 1. 通用规则

| 项 | 规定 |
|---|---|
| 基准字号 | 14px；`font_scale` 乘以全局缩放（0.8~2.0） |
| 栅格 | 8px 基准间距；容器内边距 16px；控件间 8px；分组间 16px |
| 对齐 | 标签左对齐，数值/状态右对齐，按钮文字居中 |
| 焦点环 | 键盘焦点可见（1px 描边），Tab 顺序与视觉顺序一致 |
| 主题 | **默认跟随系统深浅色**（`ThemePreference::System`，egui 侧即默认值，系统切换后下一次重绘跟随）；设置里提供三态单选：跟随系统 / 强制浅色 / 强制深色，选择即时生效并写入 `config.ui.theme`。主色用于"翻译"主按钮，错误用红、降级提示用黄 |
| 控件边框（2026-10-28 补，用户原话"浅色模式下应该有黑色边框，深色模式下应该有淡灰色边框。浅色鼠标放上去下陷整体变深颜色，深色鼠标放上去颜色变浅"） | 三态（未激活/悬停/按下）各配 1px 实线，颜色唯一出处是 `theme::edge_color(dark)`：深色 `gray(120)`、浅色 `gray(30)`。根因是 egui 亮色主题下 `widgets.inactive.bg_stroke` 本就是 `Stroke::NONE`（`style.rs` 的 `Widgets::light()`），按钮只有一层灰底没有边框，悬停才浮现一条线。悬停/按下同时做**负 `expansion`**（纯绘制层内缩，不参与布局，看起来就是按下去了一点）+ 底色变深（浅色 ×0.8 / 深色 ×1.55），按下再深一档。**栏子的分隔线不走这一处**：`Panel` 自己在靠正文那一侧画一条（`show_separator_line` 默认开，取 `widgets.noninteractive.bg_stroke`），工具条与底栏因此天然同色（详见 §2 的 A 那条 2026-10-28 补）。**幂等**：这套改动每帧都跑，必须重复应用结果不变（`widget_contrast_is_idempotent_across_frames`） |
| 失焦半透明（2026-10-28 改，FR-3.7） | 简洁窗失焦时**整窗**不透明度降到 `config.ui.unfocused_alpha`（`0.30..=1.00`，默认 0.85，设置页滑杆即时生效并持久化），走原生 `NSWindow.setAlphaValue`，标题栏/边框/红绿灯一起变淡；代价是正文文字同样变淡。拿不到原生层（非 macOS、无句柄、不在主线程）时退回只淡窗内底色的 `apply_dim` |
| 空态 | 未翻译时译文区显示灰色提示"输入后按 Enter 翻译"，不显示空白 |
| 加载态 | 主按钮变spinner+"翻译中…"并禁用重复提交；已有旧译文时用右上角细条提示"更新中"，不清空正文 |
| 破坏性操作 | 清空历史需二次确认 |
| 文案 | 简体中文；按钮用动词开头（"复制译文"而非"译文"） |

## 2. 全量模式布局（默认 1080×720）

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ A 顶部工具条（自然高度，一行 ≈61px；下沿一条分隔线，与底栏同色同出处）        │
│  [文本][图片][历史][设置]        源语言 ▾  →  目标语言 ▾     ○机翻 ●AI   悬浮窗 │
├────────────────────────────────┬─────────────────────────────────────────────┤
│ B 源文区  (50% 宽)             │ C 译文区 (50% 宽)                           │
│  ┌──────────────────────────┐  │  ┌───────────────────────────────────────┐  │
│  │ 多行编辑器               │  │  │ 只读展示（等宽衬底，可选中）          │  │
│  │ 占位：输入或粘贴文本     │  │  │                                       │  │
│  │ 滚到底不越框（D-9）      │  │  │                                       │  │
│  └──────────────────────────┘  │  └───────────────────────────────────────┘  │
│ （无页脚：字数行搬进 E 底栏）  │  缓存 · 320ms                    ← 徽标行   │
├────────────────────────────────┴─────────────────────────────────────────────┤
│ E 动作底栏（**自占一行**，v0.7 REQ-013）                                      │
│  字数 128 · 检测：英语            [翻译][复制译文][复制对照]（失败时多一颗）  │
├────────────────────────────────┴─────────────────────────────────────────────┤
│ D 状态条 (28px)  就绪 · 机翻可用/AI 未配置 · 历史 42 条 · Cmd+Enter 翻译     │
└──────────────────────────────────────────────────────────────────────────────┘
```

> **2026-10-27 变更 D（CHG-004 v0.7 / Q-018、REQ-013）**：E 这条原来是**浮在译文框右下角的动作条**（不参与布局，靠正文末尾垫一条等高空白躲它），用户要求"把右下角那几个按钮放在右下边框？和翻译多少字在一行？"并补一条硬约束"要注意按钮边框和软件里的框不要冲突或者覆盖，如果不行就把按钮调整小一点"。现改为**自占一条底栏**：字数统计与动作按钮同一行（计数左、按钮右），底栏按自然高度参与布局，两栏正文拿到的矩形就是"扣掉底栏"那块——"最后一行被按钮挡住"从结构上不成立，`bar_cover` 那套预留连同它的断言一起作废。空间不足的退让顺序固定为：**先降按钮尺寸一档**（84×28 → 64×28，只降宽度不降高度）→ **再换行**（底栏随之长高，正文跟着让）→ 字数文本可省略号截断，**按钮永远不裁掉、不压框**。同批：字数行从 B 栏脚注搬进 E，B 因此没有页脚；两栏是否等大改量**两个滚动容器的矩形**（等高、顶边对齐）。

> **2026-10-28 补（缺陷 D-11，仍属 REQ-013）**：E 这条由 `views::show` 在**窗口层**建，顺序固定为工具条 → 状态条 → E → `CentralPanel`（`CentralPanel` 会吃掉剩余矩形，排在它后面的 `Panel` 收不到位置）。第一版把这条 `Panel::bottom` 留在了 `CentralPanel` 里面，而那层的默认框架四边各 8px 内边距，于是按钮的上下留白成了**上 7、下 15**（用户 2026-10-28 原话"按钮上下留白距离不同"），条子两侧也各少 8px。现在 E 横满整窗、下沿贴住 D 状态条，按钮上下各 `BAR_MARGIN`=6px，条子顶部那 1px 是 `Panel` 自带的分隔线。**同批第二条**：E 到了窗口层就得自己画底色（`.fill(panel_fill)`）——它下面不再被 `CentralPanel` 的 `panel_fill` 盖着，而 eframe 的默认 `clear_color` 是半透明深灰，留空等于在窗口上开个透出桌面的洞。

> **2026-10-28 补（A 工具条的高度与边界感，用户第 2、3 条走查）**：A 原来把高度**钉死在 56px**，而那一排控件（页签 + 两个语言下拉 + 引擎单选 + 「悬浮窗」按钮）实测需要约 61px，钉死的结果是**换行**——工具条实际占到 82px，正文框上沿被顶下去一大截（用户原话"明明只占用一行，但是好远"）。现在 A 不再钉高度，按自然高度参与布局，`inner_margin` 上下各 `TOOLBAR_Y_MARGIN`=6px，实测正文框上沿 ≤64px（回归锁 `the_toolbar_takes_one_row_so_the_panes_sit_right_under_it`，断言里带着"钉死 56px 那一版是 82px"这个数）。**边界感**：A 与正文的分界**只有 `Panel` 自带的那条下沿分隔线**，与 E 底栏同一条代码路径、同一个颜色（`widgets.noninteractive.bg_stroke`）。第一版（同日 D-13 之前）在这里额外套了一圈 `edge_color` 的 1px 边框，用户看着截图当场退回——"太明显了，突兀，和底部栏的分割线一样颜色就行，而且两侧不需要线条"，于是整圈 stroke 作废；"界限不明显"的真凶是栏高囤积把正文顶下去 26px，不是少一条线。回归锁 `the_toolbar_separator_matches_the_bottom_bar_and_has_no_frame`（同时断言顶区只有一条横贯整窗的线、它与底栏那条同色、顶区没有整宽的描边矩形）。

## 3. 简洁模式（默认 460×160，**带原生标题栏**）

```
┌ 系统标题栏（AppKit 绘制：最小化 / 关闭，抓这里即可拖动）──┐
├────────────────────────────────────────────────────────────┤
│ ┌────────────────────────────────────────────────────────┐ │
│ │ 输入：Install the package…                             │ │ 可用高的 1/2
│ │（不随内容长高；超出可见行数在**本框内**滚）             │ │ （圆角框①）
│ ├──────────────  ≥5px 间隔（BAND_GAP）  ─────────────────┤ │
│ │ 译文：安装该包                                  ●AI    │ │ 可用高的 1/2
│ │（可滚到底，最后一行不被任何条压住；尾部 8px 是把手）     │ │ （圆角框②）
│ ├────────────────────────────────────────────────────────┤ │
│ │ [全量] [复制] [设置] [机翻|AI] [置顶] [退出]            │ │ 自然高度
│ │（行尾空白是第二处把手）                                  │ │ （窄则换行）
│ └────────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────┘
```

> **2026-10-27 变更 E（CHG-004 v0.7 / Q-017、REQ-012）**：本块的三带版式按用户第二轮走查重做。① **两带各占可用高度的近似一半**（可用高 = 窗口内高 − 动作行自然高 − 带间隔），不再"只有译文带在长、输入带永远是那一条 34px"（用户原话"我拉大界面，下面的译文框会调大，但是原文框还是原来大小，两个应该各占一半"）；这**推翻了 v0.6 Q-014 的"输入行随内容长到三行封顶"**——窗口很高时一半远超三行，两者必然冲突，用户在三个选项里裁定"多余高度 1:1 分摊、不设三行上限"，"窗口整体不因内容自动长高"这条（Q-004）保留。② **带间 ≥5px**（`BAND_GAP = 5.0`）且两带各自画成**独立圆角框**（用户原话"原文和翻译之间间隔太小，应该是两个圆角框。中间起码有5px的间隔吧"）。③ 可用高不够同时满足"输入带 ≥ 一行高（`INPUT_HEIGHT` 34）且译文带 ≥ 正文下限（`MIN_BODY_HEIGHT` 20）"时**优先保译文带**、输入带退回一行高——"谁也不能塌成零"是比"1:1"更硬的那条。④ 下限与默认随之从 130 抬到 **160**（`MIN_COMPACT_H` / `compact_rect` 默认），四处下发路径共用 `config.rs` 里的常量；动作行现在是 `Panel::bottom`、**先建**，两带的分摊只看它实测占掉多少。⑤ 动作行尾部新增一颗 `退出`（REQ-011，见 K-11）。

> 2026-10-27 变更（CHG-004 v0.6 / Q-013）：本块原画的是"无边框 + 顶部 10px 拖拽把手区"。用户看到带原生外框的实物后要求保留外框并删掉那根"小横杠"，两种形态的装饰就此统一，窗内把手从三处减为两处（动作行行尾空白、译文尾部 8px），拖动主路径改由标题栏承担；吸附判定不再只挂在"把手按下"，改由几何跳变观测补上（`02-architecture.md` §3.3 的"简洁窗的拖动"那条）。用户在同一轮里还有一句"悬浮窗需要有正常的窗口顶部栏，需要有缩小和关闭"——这两项由系统红绿灯承担，不在窗内自绘：黄灯是最小化，红灯走 P4 那条 FR-5.2 的"收起不退出"（`mode::hide` 的 `CancelClose` + `Minimized(true)` 不分形态，点 Dock 缩略图叫回）。**连带 REQ-001 的口径**：带装饰的窗口边缘缩放是系统默认能力，**不自绘缩放手柄**。

### 吸附与悬停唤出几何

```
边界矩形 = 所有显示器可见区的并集（screen::desktop()，逐屏去掉菜单栏与 Dock 后取并集）
        —— 不是"窗口所在那块屏的可用区"：两块并排放的屏中间那条接缝不是桌面的边，
           按单屏算会把窗口藏进接缝，热区收不到悬停、也量不出向内位移（2026-10-27 缺陷 D-8）。
           离屏校验（FR-3.6 的夹回）仍按单屏可用区，那条问的是"这块屏上看不看得见"。
松手时窗口 rect，只量左右两条边：
   d_left  = window.x - area.x
   d_right = area.right - (window.x + window.w)

若已停靠在左/右（锚点 = 停靠那刻下发的窗口原点，是独立状态；不能取每帧被 capture 改写的 compact_rect）：
   沿停靠轴向屏幕内的位移 ≥ snap_threshold_px(40) ──► docked_edge = None，位置原样保留（拖离）
   —— 拖离不能共用 d：藏出去后窗口在停靠轴上本就超出可用区一整个自身宽，
      d 恒为大负数，用它会每次吸回、拖离永远不成立

否则若 min(d_left, d_right) < snap_threshold_px(40)：
   右： rect.x = area.right - sliver(3)     docked_edge = Right
   左： rect.x = area.x - rect.w + sliver    docked_edge = Left
   上/下：不吸附（v0.5 起取消——藏进菜单栏/Dock 后悬停唤出不成立）
否则 docked_edge = None（自由浮动）

悬停唤出（停靠态，收起中）：
   指针进入那 sliver 的窄边 ──► 立刻整窗唤出（不补间）：右 x = area.right - rect.w / 左 x = area.x
                               docked_edge 不变，停靠态层级置为浮于其他应用之上
   指针离开窗口 ≥ 500ms     ──► 收回原位；正在窗口内按住（拖窗/选字）或输入框有焦点时不收回
   收回后指针仍压在那 sliver 上 ──► 不许立刻再弹出（闸门：指针先离开创口带再一次进入才算下一轮）
   刚吸附落位时同样置闸门      ──► 否则"拖到边上松手"会当场弹回来，看起来像停靠没生效
```

贴边后**只藏左/右**：窗口藏到那条边之外，可视区内只留 `dock_sliver_px`（默认 **3**）宽的一条热区，且它恒在屏幕最外沿——光标推到边里必然落进去，"错过它"在几何上不可能，这就是悬停唤出的前提。停靠态无论用户的置顶偏好如何都浮在其他应用之上，否则那 3px 被盖住就收不到指针事件（2026-10-23 走查实证）。夹取只处理非预期的越界：交叉轴全量夹回可视区，停靠轴仅在窗口沿该轴比可用区还长时把起点夹到 `area.min`。`sliver` 与 `threshold` 均可配置并被 `sanitize()` 夹在合理范围（`sliver` 2~24）。

> 2026-10-23 变更 A（CHG-004 v0.4 / Q-009）：本块原来的右/下两行写的是 `area.right - rect.w + sliver` 与 `area.bottom - rect.h + sliver`，与左/上不对称（算出来是窗口基本全可见、只往外多探 6px），也与"保留可见热区供拖回"相反，故改为四边对称版；连带把拖离判定改成"相对停靠锚点的位移"。
> 2026-10-23 变更 B（CHG-004 v0.5 / Q-010，**推翻变更 A 的四边对称**）：用户真机试了一次停靠就把窗口弄丢了（藏出去只剩 6px 窄边、那窄边因另一处缺陷是 6×422、`always_on_top = false` 时又被别的应用盖住，而唯一的召回手段"停靠指示"按钮自己在屏幕外）。现改为：**只认左/右两条边、热区 3px、鼠标悬停自动唤出、离开自动收回、K-07 的按钮机制作废**。同批把动作行改回正常字号（放不下换行）并把窗口默认/下限高度抬到 130px，另修"切换形态时 `capture` 把待生效尺寸冲掉"的缺陷（D-6）。
> 2026-10-27 变更 C（CHG-004 v0.6，走查三项修正）：① 简洁窗改带原生标题栏、顶部把手条删除、窗内把手减为两处，吸附判定改由几何跳变观测补上（Q-013，见 K-06 与 §3 顶部图）；② 输入行按内容长高到三行封顶、清空退回原高度（Q-014，见 K-01）；③ 吸附/停靠/唤出的边界矩形从"窗口所在那块屏的可用区"改为**所有屏可见区的并集**，两块屏相接的接缝不再算边（缺陷 D-8，见上面伪代码首行）。同批修掉"长译文滚到底最后一行看不见"（缺陷 D-9）：简洁窗是滚动容器的默认 64px 最小视口把矮栏视口抬出框外，全量窗是右下角浮层动作条盖住正文末行——两处的修法分别写在 K-02 与 `02-architecture.md` §3.3，判据落到走查表 W-2.24。

## 4. 交互流程

```
启动 ──► 恢复模式与位置 ──► [全量] 或 [简洁]
                                 │
   Cmd+Enter / Enter ──► 翻译 ──►│ 成功 → 展示 + 历史
                                 │ 401  → 提示 + "去设置"
                                 │ 未配置 → 提示 + "去设置"
                                 │ 超时 → 提示 + "改用机翻"
   Cmd+Shift+M ──► 模式切换（保留内容，瞬时切换见下）
   Cmd+Shift+P ──► 置顶开关
   Cmd+Shift+C ──► 复制译文
   Esc（简洁模式）──► 清空输入但不退出
   Cmd+W ──► 隐藏窗口，进程常驻（FR-5.2）
   Cmd+Q ──► 落盘配置后退出
```

### 形态切换（FR-3.9）

切换不是"关一个窗再开一个窗"，而是同一个窗口一次性改几何，**不做补间动画**：

```
全量 rect(F) ── 一帧 ──► 简洁 rect(C)      （反向同理）
下发顺序（同一帧内，一次性）：
  Decorations(目标形态)  ── 原生属性，只能整段设一次，逐帧设会闪
  InnerSize(目标尺寸)
  OuterPosition(目标位置)
期间：置顶层级恒定；内容（源文/译文/语言对）不动；不发起任何翻译请求；
      切换完立刻可交互，没有"动画中"这个状态。
```

> **2026-10-22 变更**：本节原为"180~220ms ease-out 形变动画"（0-35% 每帧一次 `InnerSize`、35-60% 淡出、60-100% 淡入）。真机实测（`features/CHG-004/evidence/T-001-hypothesis-verdicts.md`）证明逐帧 `InnerSize` 在 macOS 上不可用：200ms 里只有 4~5 次请求落到窗口，并复现 ~1.0s 事件循环停摆，观感是"一卡一卡的 PPT"；改用"窗内补间"（窗口先变成两端外接矩形、只插值画在里面的内容矩形）实测丝滑，但用户看过后决定**取消动画**，两个方向都做成瞬时切换。因此 `ice-app::mode::Morph` 不再实现，本节只保留"同一窗口、一次性设几何、不黑屏不闪烁"的约束。

实现约束：几何命令由 `ice-app::mode` 在切换时一次性下发（见 `02-architecture.md` §3.3），切换后立刻 `mode::capture` 回读真实几何并落盘（SIGTERM 不走 `on_exit`，只靠退出保存会丢位置）。

## 5. 走查表使用说明

P4/P5 验收时按下述步骤做，结果与截图存入 `docs/evidence/`：

1. 按第 2/3 节的控件清单逐条对照实际界面，记录"存在 / 位置符合 / 行为符合"三列结论；
2. 空态、加载态、错误态各截一张图（错误态用故意填错的 Key 制造）；
3. 缩放窗口到最小允许尺寸，确认无控件被裁掉或重叠；
4. 亮/暗主题各截图一次；
5. 键盘 Tab 顺序走一遍，确认与视觉顺序一致、无控件不可达。

截图入库规则（硬约束）：本机 `screencapture` 只能整屏采集，因此每张图必须裁剪到**只含本应用窗口所在矩形**，提交前逐张打开确认画面里没有用户其他应用的内容（代码、聊天、文档均算）；无法裁净的就不要提交，改记日志/文本证据。屏幕锁定时拍到的是锁屏壁纸，采集前先确认会话已解锁。
