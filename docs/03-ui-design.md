# 界面设计 — 全量模式与简洁模式

本文件的"控件清单"是 P4/P5 人工走查的对照表：走查时逐行勾选，位置或命名与本表不符即为缺陷。

## 1. 通用规则

| 项 | 规定 |
|---|---|
| 基准字号 | 14px；`font_scale` 乘以全局缩放（0.8~2.0） |
| 栅格 | 8px 基准间距；容器内边距 16px；控件间 8px；分组间 16px |
| 对齐 | 标签左对齐，数值/状态右对齐，按钮文字居中 |
| 焦点环 | 键盘焦点可见（1px 描边），Tab 顺序与视觉顺序一致 |
| 主题 | **默认跟随系统深浅色**（`ThemePreference::System`，egui 侧即默认值，系统切换后下一次重绘跟随）；设置里提供三态单选：跟随系统 / 强制浅色 / 强制深色，选择即时生效并写入 `config.ui.theme`。主色用于"翻译"主按钮，错误用红、降级提示用黄 |
| 空态 | 未翻译时译文区显示灰色提示"输入后按 Enter 翻译"，不显示空白 |
| 加载态 | 主按钮变spinner+"翻译中…"并禁用重复提交；已有旧译文时用右上角细条提示"更新中"，不清空正文 |
| 破坏性操作 | 清空历史需二次确认 |
| 文案 | 简体中文；按钮用动词开头（"复制译文"而非"译文"） |

### 吸附几何

```
监视器可用区 (x, y, w, h) = 去掉菜单栏与 Dock
松手时窗口 rect，d = min(到四边距离)
若已停靠（锚点 = 停靠那刻下发的窗口原点，是独立状态；不能取每帧被 capture 改写的 compact_rect）：
   沿停靠轴向屏幕内的位移 ≥ snap_threshold_px(40) ──► docked_edge = None，位置原样保留（拖离）
   —— 拖离不能共用下面的 d：藏出去后窗口在停靠轴上本就超出可用区一整个自身长/边距，
      d 恒为大负数，用它会每次吸回、拖离永远不成立
若 d < snap_threshold_px(40)：
   右： rect.x = area.right - sliver(6)
   左： rect.x = area.x - rect.w + sliver
   上： rect.y = area.y - rect.h + sliver
   下： rect.y = area.bottom - sliver
   docked_edge = 对应边
否则 docked_edge = None（自由浮动）
```

贴边后**四条边一致**：窗口藏到那条边之外，可视区内只留 6px 可见热区供拖回（左/上停靠因此必然是负坐标、右/下必然让 `rect.max` 超过可用区边界，这是机制而不是越界）。夹取只处理非预期的越界：交叉轴全量夹回可视区，停靠轴仅在窗口沿该轴比可用区还长时把起点夹到 `area.min`。`sliver` 与 `threshold` 均可配置并被 `sanitize()` 夹在合理范围。

> 2026-10-23 变更（CHG-004 v0.4 / Q-009）：本块原来的右/下两行写的是 `area.right - rect.w + sliver` 与 `area.bottom - rect.h + sliver`，与左/上不对称（算出来是窗口基本全可见、只往外多探 6px），也与下一句"保留 6px 可见热区供拖回"相反。用户选定"四边都藏"，公式改为上面的对称版。**连带改动**：拖离判定改成"相对停靠锚点的位移"（伪代码里新增的那一段），因为藏出去之后"窗口到边线的距离"恒为大负数，原来那条几何判据对四条边都再也判不出拖离。

## 4. 交互流程

```
启动 ──► 恢复模式与位置 ──► [全量] 或 [简洁]
                                 │
   Cmd+Enter / Enter ──► 翻译 ──►│ 成功 → 展示 + 历史
                                 │ 401  → 提示 + "去设置"
                                 │ 未配置 → 提示 + "去设置"
                                 │ 超时 → 提示 + "改用机翻"
   Cmd+Shift+M ──► 模式切换（保留内容，瞬时切换见下）
   Cmd+Shift+P ──► 置顶开关
   Cmd+Shift+C ──► 复制译文
   Esc（简洁模式）──► 清空输入但不退出
   Cmd+W ──► 隐藏窗口，进程常驻（FR-5.2）
   Cmd+Q ──► 落盘配置后退出
```

### 形态切换（FR-3.9）

切换不是"关一个窗再开一个窗"，而是同一个窗口一次性改几何，**不做补间动画**：

```
全量 rect(F) ── 一帧 ──► 简洁 rect(C)      （反向同理）
下发顺序（同一帧内，一次性）：
  Decorations(目标形态)  ── 原生属性，只能整段设一次，逐帧设会闪
  InnerSize(目标尺寸)
  OuterPosition(目标位置)
期间：置顶层级恒定；内容（源文/译文/语言对）不动；不发起任何翻译请求；
      切换完立刻可交互，没有"动画中"这个状态。
```

> **2026-10-22 变更**：本节原为"180~220ms ease-out 形变动画"（0-35% 每帧一次 `InnerSize`、35-60% 淡出、60-100% 淡入）。真机实测（`features/CHG-004/evidence/T-001-hypothesis-verdicts.md`）证明逐帧 `InnerSize` 在 macOS 上不可用：200ms 里只有 4~5 次请求落到窗口，并复现 ~1.0s 事件循环停摆，观感是"一卡一卡的 PPT"；改用"窗内补间"（窗口先变成两端外接矩形、只插值画在里面的内容矩形）实测丝滑，但用户看过后决定**取消动画**，两个方向都做成瞬时切换。因此 `ice-app::mode::Morph` 不再实现，本节只保留"同一窗口、一次性设几何、不黑屏不闪烁"的约束。

实现约束：几何命令由 `ice-app::mode` 在切换时一次性下发（见 `02-architecture.md` §3.3），切换后立刻 `mode::capture` 回读真实几何并落盘（SIGTERM 不走 `on_exit`，只靠退出保存会丢位置）。

## 5. 走查表使用说明

P4/P5 验收时按下述步骤做，结果与截图存入 `docs/evidence/`：

1. 按第 2/3 节的控件清单逐条对照实际界面，记录"存在 / 位置符合 / 行为符合"三列结论；
2. 空态、加载态、错误态各截一张图（错误态用故意填错的 Key 制造）；
3. 缩放窗口到最小允许尺寸，确认无控件被裁掉或重叠；
4. 亮/暗主题各截图一次；
5. 键盘 Tab 顺序走一遍，确认与视觉顺序一致、无控件不可达。

截图入库规则（硬约束）：本机 `screencapture` 只能整屏采集，因此每张图必须裁剪到**只含本应用窗口所在矩形**，提交前逐张打开确认画面里没有用户其他应用的内容（代码、聊天、文档均算）；无法裁净的就不要提交，改记日志/文本证据。屏幕锁定时拍到的是锁屏壁纸，采集前先确认会话已解锁。
