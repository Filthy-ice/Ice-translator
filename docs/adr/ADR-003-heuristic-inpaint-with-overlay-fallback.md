# ADR-003 图片回写：启发式擦除 + 覆盖层兜底，不引入学习型 inpainting 模型

- 状态：已接受
- 日期：2026-10-19
- 关联：FR-2.4、FR-2.5、FR-2.7、FR-2.8、R-3、R-6
- 范围约束：立项书第 3 节"明确不做"

## 背景

"把中文画回图片"需要三步：擦除原文、决定译文版式、绘制文字。学习型图像修补（LaMa/SD inpaint）能处理复杂背景，但模型体积 100~200MB、需要 ONNX/PyTorch 运行时、单张耗时秒级，且对自用工具是明显的过度投入。

## 决策

v1 采用**两级输出**，由同一套块级计划决定每个块用哪一级：

1. **回填级（Replaced）**：适用于背景近似均匀或可估计的区域。
   - 从块框边缘一圈采样，取颜色直方图众数作为背景色；
   - 用背景色实心填充原文区域（可选 1~2px 高斯过渡边），再绘制译文；
   - 前景色取框内与背景色差最大的像素簇众数，保持原颜色；
   - 字号从框高估算（`0.75 × 块高`），按目标语言的宽度系数自适应缩放，下限为原字号 55%。
2. **覆盖层级（Overlay）**：当边缘采样的颜色方差过高（判定为复杂背景），或译文缩放到底仍超出框容量时，改为在原文位置绘制带底色的译文块，不擦除像素。

判定阈值（颜色方差、容量估算）以真实样图集调参，参数集中在 `CompositeOptions`，不散落在渲染代码里。

## 理由

- 覆盖率优先于完美：截图/网页/说明书里大多数文字块背景可估计，启发式够用；剩下的一小部分有覆盖层兜底，不会产出"读不懂"的图。
- 无模型依赖，`ice-vision` 保持纯 Rust + 系统能力，构建与体积可控。
- 两级结构给未来留出位置：若要接真 inpainting，只需替换第 1 级的擦除步骤，块级计划与渲染接口不变。

## 影响

- 明确写入已知限制：照片、渐变、纹理、压在图形边缘上的文字无法做到无痕回填，只能覆盖层。
- 覆盖层需要"看起来不突兀"的底色策略（半透明深色底 + 白字），这是审美判断，验收时用人工评分而不是断言。
- 中文/日文渲染需要 CJK 字体：优先 Core Text 枚举系统字体（PingFang SC / Hiragino Sans / Noto Sans CJK），找不到则回退到 `egui` 自带的比例字体并明确报告"缺字形"而不是静默出方块。
