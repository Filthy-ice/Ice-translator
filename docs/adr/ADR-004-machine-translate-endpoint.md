# ADR-004 机翻通道端点选型：MyMemory 免费 GET 端点 + 450 字符切块

- 状态：已接受
- 日期：2026-10-19
- 关联：需求基线 §4.2（机翻零配置）；FR-1.2、FR-1.3、FR-1.6、FR-1.7、FR-1.9、NFR-1、NFR-2、NFR-3

## 背景

需求基线 §4.2 把机翻定义为"零配置可用"：用户装上就能翻，不需要注册、不需要提供 Key。
这排除了所有需要凭据的商业机翻 API（DeepL / 百度 / 腾讯 / 有道都要求 Key 或配额账号），
剩下可选的是少数公开免费端点。P1 记录过一条硬事实：本机网络连不上
`translate.googleapis.com`（连接失败，与 GitHub SSH 端口被拦是同一类出口限制），
而 `api.mymemory.translated.net` 可用。P3 实施时对本机可达性做了复测，并实测了它的行为边界。

## 决策

1. 机翻通道使用 `https://api.mymemory.translated.net/get?q=<text>&langpair=<src>|<tgt>`，
   常量集中在 `ice_providers::machine::DEFAULT_ENDPOINT`，引擎可由 `with_endpoint` 指向别处（测试用本地假服务）。
2. **单次查询 450 字符**（`MACHINE_QUERY_CHARS`）。上游写死 500 字符上限，留出余量给占位符与语言参数。
3. 超长文本先 `protect` 再 `chunk_chars` 切块，逐块请求后按序相接；块数回传给界面（`segments`）。
4. 语言码直接用 `Language::code()`（`zh-CN` / `zh-TW` / `en` / `ja` …），与该端点的取值习惯一致，不另建映射表。
5. 源语言"自动检测"由本地 `ice_core::detect()` 完成，端点不接受 `auto`；判不出来时按 `en` 请求并把回显留空。
6. 错误判定必须看**响应体**的 `responseStatus`：实测超限等情况 HTTP 仍是 200，错误写在 body 里
   （`responseStatus: "403"` + `responseDetails: "QUERY LENGTH LIMIT EXCEEDED..."`）。
   该字段既可能是数字也可能是字符串，因此归一化为 `u16` 后比较；非 200 一律 `ProviderError::Status`，
   形态不认识一律 `Decode`，**绝不把错误文本当成译文返回**。
7. 只重试网络类失败（超时、连接失败），最多额外 2 次；body 级错误不重试（重试不会改变结果）。

## 理由

- 无 Key 可用是硬需求（FR-1.3 要求双引擎随时可切，§4.2 要求机翻零配置），可选面本来就窄，实测可达的只剩这一条。
- 450 而不是 500：切块超限的报错是 body 级的，若不留余量就会以"翻译失败"的形式暴露给用户，
  而这类失败看起来和服务挂了无法区分。
- 把端点做成可注入而不是硬编码在请求处：本包全部 HTTP 行为都能用本地假服务覆盖，
  真实端点只剩两条 `#[ignore]` 测试负责"契约仍然成立"。
- `responseStatus` 的双重形态与 body 级错误是这个免费端点的真实行为，写进 ADR 而不是只留在代码注释里，
  否则将来换端点的人会以为可以只看 HTTP 状态码。

## 影响

- 正面：装完即用，机翻不消耗任何用户额度；`ice-vision` 的图片文字（P7）可以直接复用这条通道。
- 代价与约束：
  - 免费服务的配额与限流不受我们控制，`ja→zh` 这类命中翻译记忆的结果质量较差（P1 实测记录）。
  - 单次 450 字符意味着长文必然多次请求，延迟随段数线性增长，且免费端点抖动明显（P3 两轮实测：单句 731 / 2133ms，1060 字符 3 段 1.9 / 3.2s）。
  - 该端点会收到用户原文（HTTPS 传输，服务端可见），这是"零配置"的固有代价；
    需要私密性的内容应改用 AI 通道（用户自己的 Key）或后续离线方案。
- 失效条件与降级路径（触发即按 spec 的停止条件记 SPEC_DEVIATION，不静默换端点）：
  1. 端点整体不可达或持续返回 body 级错误 → 界面提示"机翻暂不可用，请改用 AI 通道"；
  2. §4.2 预留的降级方案：内置离线词表 + 需用户自备 Key，实现前需在 `docs/01-requirements.md`
     先变更登记原因；
  3. 若将来需要更高质量，可换成用户自备 Key 的商业机翻，`MachineTranslateEngine` 的注入点已为此保留。
- 淘汰记录：`translate.googleapis.com`（本机 TLS 建连失败，15 秒超时，与 P1 记录一致）；
  各类需 Key 的商业机翻（违反 §4.2 的零配置约束）。
