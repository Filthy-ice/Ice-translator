# V-010 真机运行证据（2026-10-20，macOS，debug 构建）

三件事：启动时序、单实例双开、空闲 CPU 占用。全部在用户真机上取，`RUST_LOG=info`，ANSI 码已剥除。
隐私核对：不含源文、译文、端点查询串、密钥明文；Key 只以 `key_len` 与 `key_hash8` 出现。

## 1. 启动时序：窗口先建好，钥匙串在后台线程读（REQ-005 / TC-4.2-b / W-1.18）

`09:24:49` 取得单实例锁并建窗，`09:25:07` 钥匙串才返回——中间 18 秒是用户在 macOS 系统授权框上点"始终允许"的时间。
这期间窗口一直在渲染。修复前读取排在建窗之前，同样的授权框会让窗口根本出不来（表现为"启动卡死"，12s 后被 timeout 杀掉、`config.toml` 一次未写）。

```
2026-10-20T09:24:49.513242Z  INFO ice_translator: 取得单实例锁 pid=21841 path=…/IceTranslator/ice-translator.lock
2026-10-20T09:25:07.796782Z  INFO ice_translator::app: 读到 API Key key_len=35 key_hash8="d5477b63"
```

## 2. 单实例双开（REQ-009 / TC-9.1-a / W-1.19）

第一个实例（pid 21841）在跑，再启动一次：

```
$ RUST_LOG=info timeout 15 ./target/debug/ice-translator
2026-10-20T10:22:23.583224Z ERROR ice_translator: 无法启动：单实例锁被占用或不可写 pid=21841
Ice Translator 已在运行（PID 21841）。
如果确实没有窗口，说明上次异常退出留下了锁文件，
可在配置目录删除 ice-translator.lock 后重试。
$ echo $?
1
```

核对结果：

| 检查 | 结果 |
|---|---|
| 第二个实例退出码非零 | ✅ `1` |
| 提示可读、说出持锁者 PID、并给出自愈办法 | ✅ 中文三行，含 `PID 21841` 与"删除 ice-translator.lock 后重试" |
| 不泄露 `config.toml` / `history` 路径细节 | ✅ 只说"配置目录"（单测 `second_acquire_in_same_dir_is_rejected_while_holder_lives` 同样断言） |
| `config.toml` 未被触碰 | ✅ mtime+size 前后一致（`1792491287 598`） |
| `history.jsonl` 未被触碰 | ✅ mtime+size 前后一致（`1792491348 746`） |
| 第一个实例仍活着 | ✅ `pgrep` 仍返回 21841 |
| 锁文件仍是第一个实例的 PID（没被第二个删掉） | ✅ 内容为 `21841`，对应单测 `release_does_not_remove_someone_elses_lock` |

陈旧锁接管也在真机复现过：先前 `kill` 掉旧实例后重启，锁被自动清除并接管（`/tmp/ice-live2.log`），对应 TC-9.1-b。

## 3. 空闲 CPU 占用（NFR-2 / FR-5.2 / TC-N-1 / W-1.20）

窗口开着、无提示条、无在飞请求，静置 30 秒，用 `ps -o cputime` 取前后差值（`ps -o %cpu` 是进程生命周期均值，测不出空闲段）：

```
起始 CPU 时间 0:15.62 → 结束 0:15.62
采样窗口 30.2s，期间消耗 CPU 0.000s → 占用 0.0000%
NFR-2 / FR-5.2 要求空闲 < 1%： ✅ 通过
ps 生命周期均值 %cpu=0.0 · RSS=93.3 MB
```

**30 秒内消耗 CPU 恰好为 0**，不是"低于阈值"而是"一次都没醒"。这印证了 `app.rs::ui` 的实现：只有提示条到期与结果到达才请求重绘，空闲帧不主动唤醒（对应 TC-N-1 的代码审查项）。
累计的 15.62s 是启动 + 渲染 + 7 次真实翻译（见 V-011 证据件）的总开销。
