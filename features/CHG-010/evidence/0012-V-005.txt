CHG-010 批准前取证读数汇总（六轮，仓外 /tmp/sel_poc，探针不进仓）
本文件是我把各轮终端读数逐条抄下来的转录，原始 out.log 在 /tmp（跑完即弃）。

第 1~3 轮（eframe 遮罩 + 注入鼠标）
- 建窗即被 AppKit 夹进可用区：CGWindowList `layer=3 bounds=0,63,1920x953`
- 注入五段拖框（拖新框 / 右下把手 / 距角 8 点 / 框内移动 / 拖出屏外）：
  pressed=5 drag=21 released=5；夹取那一下停在 `1750,917,1920,1080`；
  把手 `900,637 → rect 1012,731,1162,856`（只动那一个角）
- 主窗 Visible(false)@21.0 → Visible(true)@25.0，三个时刻整屏采样逐点相同
  （(400,15)=(220,30,30)、(400,1060)=(14,41,99)、(1700,900)=(98,98,13)）
- 遮罩存在时 `screencapture -x -o -R0,0,1920,1080` real = 0.08 / 0.07 / 0.09 秒

第 2 轮的教训：uv 传成像素坐标 → 整屏读成一个颜色，差点被判成"遮罩画的是别的窗"。
改对之后四象限 + 白标记逐点核对通过（(100,100)=(115,115,115) = 255×0.451）。

第 3 轮（原生 setLevel(25) + setFrame）
- AppKit frame `0,-31,1920x1080` → `0,0,1920x1080`；winlist `layer=25 bounds=0,0,1920x1080`
- 抬层后在 `y=1060..1076`（Dock 那条）与 `y=8..24`（菜单栏那条）各拖一次框，都出选区
- 未激活时 `makeKeyAndOrderFront` → `key=false`；注入 esc 后 `MASK-KEY` 计数 0

第 4 轮（两块屏各一扇遮罩）
- 副屏那扇建出来被夹成 `-1920,-120,1920x1137`；抬层对位后 `layer=25 bounds=-1920,0,1920x1200`
- 副屏 `visibleFrame == frame`（它上面没有菜单栏可让）

第 5~6 轮（"写完不等于生效"）
- 同一轮内：AppKit 两次回读都是 `level=25 frame=0,0,1920x1080`（8.6s / 10.087s），
  而窗口服务器 9.4s 仍报 `layer=3 bounds=0,31,1920x1080`，副屏那扇仍报抬层前的形状
- 激活是异步的：`key=false` 从 8.500 持续到 8.604，8.612 才 `key=true`
- 另一次（Swift 自建进程）没能把自己激活：`isKeyWindow` 全程 false —— 那次的 `key=false`
  不能当"hide 之后焦点会不会回去"的证据，那一格仍待真应用实测（W-6.6）

多屏抓屏形状（实施时量的）
- 不带 `-D` 的静默抓图只产出主屏一张（1920×1080）
- `-D1` → 1920×1080，`-D2` → 2240×1400（用户把副屏改成 2K 之后复测），两张合计 0.216 秒
- `-R` 拒绝负坐标（`-R requires a valid rect`），副屏只能走 `-D`
- 副屏形状在两次量测之间从 `(-1920,-120) 1920x1200` 变成 `(-2240,-320) 2240x1400`
  ⇒ 屏列表每次截图前重新读，不缓存
